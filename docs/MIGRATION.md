# V2 签名语义与旧版兼容

## 新旧格式

| 项目 | 旧版 | V2 |
| --- | --- | --- |
| 文本处理 | GUI 会 strip 两端空白 | 按 UTF-8 编码，保留空格与换行 |
| 文件处理 | 提取 TXT/PDF/DOCX 的文字后计算摘要 | 原文件全部字节，包括格式和元数据 |
| SM2 输入 | 64 字符 SM3 十六进制文本的 ASCII 字节，无 ZA | gmssl 的 SM3(ZA || 原文字节)，固定 ID 1234567812345678 |
| 导出 | 无标记 r||s 十六进制 | SM2SM3-V2: 前缀 + r||s 十六进制 |
| 验证选择 | 显式勾选旧版兼容 | 默认 V2，拒绝自动降级 |

V2 的原文 SM3 摘要仅用于展示，不是送入 sign_with_sm3 的消息。不要把展示摘要再传进去签一次。

旧版文件签名只绑定提取文字，不能证明整份文件字节没变化。使用旧版兼容验签通过时，也只能按旧语义解释结果。

## 更新前

1. 保留自己的旧 keys/、signatures/ 和原文件备份，不提交到 GitHub。
2. 更新源码不会自动删除或迁移旧密钥、旧签名。
3. V2 可继续使用有效且匹配的旧密钥；不用为了升级生成新密钥。
4. 如主动生成新密钥，界面会确认覆盖，请先保存旧公钥。旧私钥无法从公钥恢复。
5. 两个密钥文件不是原子成对存储；若写入中断，重新加载时会校验一致性并拒绝不匹配的密钥。

## V2 使用

签名页输入文本或选择文件，点击对应签名按钮。导出文件带版本标记，私钥不会写进签名文件。

验签页导入可信来源的公钥，粘贴或导入签名，使用对应的文本/文件验签按钮。页面的篡改测试只修改内存临时副本，不改原文件；错误公钥测试使用另一个有效密钥，不把格式错误异常冒充验签失败。

验签通过仅表示所选公钥对这些字节的签名匹配，不证明公钥真实属于某人，也不提供证书链、可信时间戳或文件保密性。

## 旧版验证

默认不接受无标记签名。确实要验证本项目旧版产物时勾选“允许旧版无标记签名”，使用旧公钥和原始资料。

API 的 sign(digest) / verify(digest, signature) 保留历史行为；新代码使用 sign_message(bytes) / verify_message(bytes, versioned_signature)。不要把旧签名改个前缀就当成 V2。

## 互操作范围

固定 SM2 曲线、SM3、ID 1234567812345678、同一条消息字节。OpenSSL 侧使用 DER 编码的 r/s，应用导出使用固定宽度 r||s，并增加应用版本标记，转换由独立测试辅助程序完成。

这不是直接兼容任意 OpenSSL 命令、PEM/证书、TLS、DNSSEC 或其他 SM2 业务协议的承诺。ID、字节编码和签名格式必须一致。
